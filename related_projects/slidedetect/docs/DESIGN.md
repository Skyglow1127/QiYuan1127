# SFLS 拉莫尔频率计设计说明

## 规格解释与实现边界

本项目目标为对已经整形的 70–350 kHz 拉莫尔数字信号测频，输出更新率为 1 kHz。输入不是以 1 kS/s 采样的模拟正弦。RTL 核心不依赖 ARM、Vitis、浮点软件或 testbench 运算完成测频。

0.001 Hz 是待验证的测量性能指标，不等同于输出的小数位数。输出采用无符号整数微赫兹（1 µHz = 10^-6 Hz），便于单独观察数值量化误差。物理前端、实时时基误差及磁力计标定不在 RTL 仿真保证范围内。

## 两种配置

| 参数 | 常规配置 | 长窗口配置 |
|---|---:|---:|
| CLOCK_HZ | 100000000 | 100000000 |
| WINDOW_LOG2 | 15 | 15 |
| 保留时间戳数 M | 32768 | 32768 |
| EDGE_STRIDE D | 1 | 64 |
| 输出周期 | 1 ms | 1 ms |
| 350 kHz 下窗口跨度 | 93.62 ms | 5.99168 s |
| 70 kHz 下窗口跨度 | 468.10 ms | 29.9584 s |

每 D 个物理上升沿保留一个时间戳。这是对原论文的工程扩展：保留事件仍等间隔于周期序号，回归模型保持线性，但最终求频公式需乘以 D。普通和长窗口分别验收，不能称长窗口仍有毫秒级响应。

第一帧需填满 M 个保留事件，之后每 1 ms 对已提交的统计量做快照。固定事件数不等于固定时间窗口。长窗口配置是证明静态精度可达的一种选择，不是推荐直接用于快速变化磁场的最终产品参数。

## 算法与位宽

输入 c[j] 为 64 位无符号计数时间戳；j = 0..M-1。

```
w[j] = 2*j - (M-1)
S = sum(c[j])
Q = sum(w[j]*c[j])
K = M*(M*M-1)/6
frequency_uHz = round(CLOCK_HZ * D * K * 1_000_000 / Q)
```

所有累加量与中间量为 96 位。初始化 n 点窗口的递推为：

```
Q_next = Q - S + n * new_timestamp
S_next = S + new_timestamp
```

满窗移出 a、加入 b：

```
Q_next = Q - 2*S + (M+1)*a + (M-1)*b
S_next = S - a + b
```

两个表达式均使用更新前的 S。M 为 2 的幂，满窗中的常数乘法变为移位和加减。每个保留事件有固定数量的更新操作；初始建窗仍需 M 个事件。BRAM 不执行整阵列复位，通过 count/full 防止未初始化值进入有效结果。

除法器使用 96 步 restoring division，最后按余数四舍五入。对外测得从采样请求到 valid 的总延迟为 98 个时钟周期（100 MHz 时 0.98 µs）；统计快照只使用请求时已经提交的事件。该计算延迟与几秒的窗口延迟是两回事。

测试覆盖 WINDOW_LOG2=3、7、15，EDGE_STRIDE=1、64；任意其他参数组合并未全部验证。扩大窗口或 D、提高时钟、修改输出尺度前必须重新核算 96 位分子上界；不可假设参数无上限。

## 接口与错误处理

顶层文件为 `rtl/lamor_frequency_meter.sv`，模块同名（保留工程当前命名）。

| 信号 | 含义 |
|---|---|
| clk | 100 MHz 已校准时基/处理时钟 |
| rst | 高有效同步复位；须按接口时序供给 |
| larmor_in | 已整形、满足 FPGA 电平的异步输入 |
| frequency_uHz | 微赫兹整数，valid 时读取 |
| result_valid | 一个时钟周期宽的结果脉冲 |
| window_full | 已完成建窗 |
| result_last_tick | 本次估计包含的最新事件时间戳 |
| result_mean_tick | 窗内事件时间戳算术平均，向下取整到 tick |
| input_timeout | 连续 10 ms 无物理输入边沿，置位锁存 |
| fault | 核心协议异常或输入超时，复位前保持 |

`result_mean_tick` 不是严格的物理窗口中点，也不是可保证无偏的瞬时估计时间；动态报告分别比较平均事件时刻和最新事件时刻的真值。输出到达时间还包含定时快照和除法延迟。

事件处理需要 3 个时钟周期，最大目标输入事件间隔约 285 个时钟，因此吞吐有余量。若事件源违反 ready、时间戳重复/倒退，或者计算尚忙又收到采样请求，核心锁存 fault。接口没有无限队列或反压恢复；复位重新建窗。

无输入时，最长 10 ms 后告警。在告警之前可能继续输出旧窗口估计，应用应检查 result_last_tick 的新鲜度。硬件没有声称能够检测所有漏脉冲/多余边沿：某些错误周期仍在测量范围内。此类前端失真需要额外质量诊断。

## 量化误差上界与长窗口代价

对恒频信号，设每个采样时间戳误差都落在宽度为一个 tick 的区间内（可相关；固定同步延迟可并入截距）。对于偶数 M，最坏斜率误差满足：

```
delta_m <= 3*M / (2*(M*M-1))  [ticks / retained event]
m = CLOCK_HZ * D / f
abs(delta_f) <= CLOCK_HZ * D / (m - delta_m) - f
```

100 MHz、M=32768、D=64、f=350 kHz 时，上界约 0.00087619 Hz，另加输出舍入最多 0.0000005 Hz。在相同假设下，上界随 f 增大，因此该值覆盖 70–350 kHz 静态频率范围。这不是有噪声或时基误差时的整机保证。

D=1 时相应最坏上界约 0.05608 Hz，说明不能从独立白量化噪声公式直接推断所有频点的毫赫兹性能。上界保守，实测仿真通常低于它。

亚稳态引起的额外整周期延迟、随机抖动、时基漂移、漏脉冲不满足上述单 tick 模型。1 ppm 时基偏差在 350 kHz 附近产生约 0.35 Hz 误差。若要求绝对误差 0.001 Hz，仅时基这一项约需 2.86 ppb，不能靠增加输出位宽解决。

## 验证分层

1. **时间戳回放**：以 Python 直接求和 LS 为独立 oracle，在 XSim 中加速输入事件；这验证全部 RTL 运算，但不声称仿真时间与物理时间相同。
2. **完整 RTL 时钟仿真**：以绝对事件时刻驱动异步数字输入，真实运行 100 MHz 时钟，覆盖同步器、周期抽取、建窗和 1 kHz 调度。
3. **异常与算术单元**：验证舍入、除零、过载、重复/逆序时间戳、忙时请求、复位恢复和输入超时。
4. **布局布线后 SDF**：对实际路由网表执行启动与边沿采集短用例；完整长窗口准确度仍由 RTL 回归验证，不能称已做全部频点的长时间门级回归。
5. **器件时序**：在 K26 上进行 OOC 综合/布局/布线；同时查看 setup、hold、pulse-width 和 DRC，而非仅看 WNS。

## 时序约束与上板边界

约束是核级 out-of-context 接口约束，不含板级管脚映射。clk 周期 10 ns，不确定度 0.1 ns；rst 按上游同步逻辑在时钟沿后 0.5..2.0 ns 到达定义；输出外部数据通路延时预算为 0.2..2.0 ns。这些最小/最大延时合同必须在后续系统集成中兑现，不能直接接异步机械复位或把 OOC 的保持时间结论用于任意板级连接。最初将无物理接收端口的最小延时设为零产生了端口保持时间违例；最终核级验证采用明确的接口合同，没有屏蔽内部保持路径。

仅 larmor_in 到第一同步级 D 设置 false path，第二同步级及后续路径仍计时。CDC 工具对未定义源时钟的异步端口不会给出完整跨时钟证明；双触发器结构、ASYNC_REG 和输入扰动测试不等于实际 MTBF 或模拟亚稳态验证。

本次不生成可直接烧写 KR260 的 bitstream。后续上板需增加时钟/复位来源、实际引脚、电平约束和数据读出接口，并重新做完整系统实现。
