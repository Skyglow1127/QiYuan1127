如果可靠测量和原生执行接口下仍无法达到任务需要的静态精度，应先修复驱动、舵机、供电或机构。上层调度不能保证克服物理能力不足。当前证据还不能判定是哪一种。

## 已实现的执行方式

`shared_progress_v1` 为六个臂轴维护一个共同的原轨迹时间进度。反馈落后时共同降速，保留已检查路径、原拐点和终点。旧的默认执行方式继续保留。

- 源路径使用原解析位置、速度、加速度；相位变速预算考虑 `q'' = q_ref'' * phase_rate² + q_ref' * phase_acceleration`。
- 为给相位变速留余量，最大相位速度为0.8。源曲线配置5°/s、10°/s²，控制后的参考峰值上界为4°/s；具体预算记录在方法摘要及执行结果中。
- 每次提交前检查整组六轴裕量，组内不再为某一轴单独等待推进。逐轴提交期间继续检查健康、取消和裕量；失败会停止剩余指令，不能撤回先前已提交的轴。
- 保留2.5°候选裕量、3°跟踪故障、1°终点误差和连续新反馈稳定要求。稳定残差不会通过积分偏移或放宽容差转为成功。
- 新策略对所需关节反馈设置2秒恢复上限，避免某一轴长期失效而其他轴持续更新时无限等待。旧策略的反馈超时语义保持原样。
- 原始参考起点时间不被门控改写；记录相位、真实主机时钟、组编号、各轴提交与回执。回执、主机接收时标均不冒充舵机采用或采样时标。

解析导数约束适用于不中断的模型参考。ACK等待、反馈恢复及实际舵机插补可能改变墙钟时间下的运动连续性。没有声称硬件同步、缓存插补或实物速度/加速度已得到保证。

## 使用

新方法首先限制为固定READY姿态，作为抓取前执行能力验证。目标、路径和参数保存在review中，一次明确批准绑定一次执行，之后自动采集日志并在成功或失败后生成量化报告。

```bash
# 显示入口；不连接设备。
./执行轨迹闭环.sh --help

# 纯软件演示准备；不会访问设备。
./执行轨迹闭环.sh prepare --method method02_shared_progress --mode demo

# 实机准备：只读关节状态并规划，输出具体目标、全部路径与参数。
./执行轨迹闭环.sh prepare --method method02_shared_progress --mode live
```

执行使用同一入口的`execute`子命令，提供保存的`method_review.json`与用户对该具体方案的批准文字。准备和执行分开，准备不会自动上电或运动。`execution_contract.json`将现役 Linux 程序及库的核查结果、尚未确认的舵机目标覆盖语义绑定进review。2026-10-27 已通过实际进程、映射库与关键路径反汇编核对当前部署；舵机固件及物理精度仍未认证，`deployment_verified=false` 保留为完整部署未认证，`host_deployment_identified=true` 表示主机侧身份已查明。证据位于 `validation/native_probe_20261027/deployment/`。

运行结束后，`logs/<run>/method_summary.json`的`execution_metrics`指向自动量化结果。量化失败会保留原运动结果并单独记录分析错误。

已有证据可以独立重算，输出必须使用新目录：

```bash
python3 tools/analyze_execution.py --stage-dir /绝对路径/executed --output /绝对路径/新报告目录
```

工具只使用标准库，保存输入与分析器SHA256，输出JSON、HTML、CSV。原始时间轴误差按覆盖时间加权；反馈缺口、拒绝帧和保留旧值被单独标记。静态残差需要最终目标有提交及正回执、稳定窗口样本和时长充分等条件；否则保持未知，不构造假终点。

2026-10-27只读准备时，配置中的D1网口`enp99s0`处于DOWN且无IP，SDK未能建立DDS域；没有发送运动指令。新入口已增加本地连接预检。当前无法据此取得真实起点或验证部署版本；恢复D1连接后再生成新的实机review。其他网口不会被自动选用。

验证记录见[软件验证结果](validation/software_validation.json)。本版本没有自动执行实物抓取。
# 带时间的整组下发代码（2026-10-27）

本次新增 `timed_group_v1`：上层将批准的六轴参考与原相对到达时间分块预存到机载，机载建立唯一 `steady_clock` 起点，在每段起点成组发送下一段终点及该段时长。正常下发不逐轴等待 ACK 或到位；定时路径不再套用旧 `delay` 换算。串口仍顺序写各轴，记录提交时差，不声明电机硬件同步。

上层实现为 `timed_group_transport.py`、`sdk_timed_executor.py` 与 `host_src/timed_trajectory_bridge.cpp`；机载实现位于 `onboard_fix_20261027/controller/` 和私有 `library/`。已接入 `hardware_bridge.py` 的 `--scheduling-policy timed_group_v1`，以及现有规划、manifest 和阶段执行链。`执行带时轨迹.sh` 提供固定 READY 的 prepare/execute 入口，仍使用保存的具体路径和原批准流程。

机载按下一组截止时间安排有超时预算的逐轴查询；坏包、错 ID、错命令和错长度不进入角度帧，查询失败不刷新旧角度。正常轨迹中重复的 0.1° 编码目标会跳过。发送超期明确失败，不积压补发或静默重置时间；暂停与恢复共用整条轨迹时钟。J6 仅保留实测快照，终点依有效新反馈判断，不重试或改目标。

按用户最新要求，这一版本仅编写代码，**未编译、未测试、未部署，未执行机械臂动作**。`onboard_fix_20261027/deploy_controller.py` 也仅为未运行的部署代码；实际控制器仍是核查时的旧版本。
